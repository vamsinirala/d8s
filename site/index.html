What it does

Multi-environment comparison

Pick any set of environments — any mix of clusters and namespaces — and see what's present, what's missing, and how many fields differ for every resource kind.

Field-level diff

Drill into any resource for a path-by-path comparison, filtered by probes, resource limits, env vars, volumes, images or config data.

Image version drift

One table showing every deployment's image tag across environments, so version drift is obvious without opening a single resource.

Deployment bundles

See everything a deployment references and everything referencing it back — including dangling references pointing at resources that don't exist.

Secrets stay secret

Secret values are hashed server-side before they reach the browser. You can tell that two secrets differ; you never see their contents.

Runs entirely local

Uses your existing kubeconfig and auth plugins. Nothing is uploaded anywhere — there's no backend service and no account.

Get started

# Download the latest release bundle, then:
tar -xzf d8s-<version>.tgz
cd d8s-<version>
./start.sh          # start.cmd on Windows

Needs Node.js 20+ and a working kubeconfig. Or run from source: npm install && npm run dev.

Note: D8s runs on your machine, not here. The demo above uses sample data so you can explore the interface — the real tool needs local access to your kubeconfig and clusters.

FAQ

How do you compare Kubernetes configs between dev, staging and prod?

Define each environment as a kubeconfig context plus a namespace, then compare them all at once. D8s shows which resources exist where, how many fields differ, and a path-by-path diff covering probes, resource limits, environment variables, volumes and image tags.

How do you find Kubernetes configuration drift between environments?

Drift shows up as fields that differ where they shouldn't — missing CPU or memory limits in one environment, mismatched container image tags, or a ConfigMap that exists in staging but not production. D8s surfaces all of these in one view, with a dedicated report for image version drift.

Is D8s free and open source?

Yes — free and open source at github.com/vamsinirala/d8s. It runs locally using your existing kubeconfig. No account, no hosted service, no data leaving your environment.

Does D8s expose Kubernetes secret values?

No. Secret values are hashed server-side before reaching the browser. You can see that a secret differs between environments, or that a key is missing, without ever seeing its contents.

What does D8s work with?

Any Kubernetes cluster reachable from your kubeconfig — EKS, GKE, AKS, or self-managed — including exec-based auth plugins like aws eks get-token and kubelogin. It compares Deployments, StatefulSets, DaemonSets, ConfigMaps, Secrets, Services, PersistentVolumeClaims, Ingresses, PodDisruptionBudgets and HorizontalPodAutoscalers.
